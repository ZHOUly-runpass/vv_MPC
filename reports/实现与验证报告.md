# R680-C16 算法项目实现与验证报告

更新时间：2026-08-24

## 已实现

- 配置加载、23 项实车验证门、默认 `perception_only` 和非零命令硬锁。
- C16 点云有限值/零点/自车/ROI 过滤，确定性 BEV 特征契约。
- 欧式聚类、PCA 包围盒、二维占据栅格、恒速 Kalman 跟踪与协方差传播。
- 差速、滑移转向、麦克纳姆、全向和 Ackermann 五类运动学、限幅与候选 rollout。
- 七角色候选轨迹、解析约束过滤、Top-K 求解流程。
- 圆形保守包络、不确定度膨胀、离散 D-CBF 诊断。
- CasADi/IPOPT 多重射击 MPC；参考轨迹验证器用于未解锁的感知阶段。
- 命令转换、超时/数据陈旧/急停/求解失败/运动锁监督与故障锁存启动状态机。
- 冻结 LiDAR 主干协议、确定性替代后端、PyTorch 特征适配器、多候选头和安全预测头。
- 路线重采样、坐标变换、代价地图通道、特征缓存、哈希校验和伪标签结果分类。
- ROS 2 Humble Python 包、launch 文件、只读 ROS 图审计、开发机编译和零速实启脚本。

## 验证结果

- Windows 本地：23 项单元/集成测试通过。
- 配置校验：通过；`motion_unlocked=False`，23 个验证门保持关闭。
- 合成 C16 闭环：检测到 1 个障碍，输出 `[0, 0, 0]`。
- 开发机：Ubuntu 22.04、ROS 2 Humble、Python 3.10、colcon 可用。
- 开发机 CasADi 3.7.2：`Solve_Succeeded`，状态有限；冷启动约 207–215 ms。
- ROS 2 colcon：`r680_safety_planner_ros` 编译成功并生成 `planner_node`。
- ROS 实启：`/cmd_vel` 的线速度和角速度全部为 0；状态为 `commissioning_lock`。

## 仍不能解锁的外部条件

当前代码达到“安全锁闭的可运行工程骨架”，不等于已具备实车自动行驶资格。下列事项必须依赖实车、驱动、数据或 checkpoint，代码不能代替实测：

- R680 精确车型/运动形式、有效 URDF、参考点、轮廓、轴距/轮距和物理极限。
- C16 精确子型号、驱动分支、PointCloud2 字段/频率/时间戳和雷达到车体外参。
- `/odom`、IMU、TF、全局路径和局部代价地图的真实话题与 QoS。
- 控制正负方向、控制延迟、制动距离、丢指令停车、物理/软件急停。
- UniLION 纯 LiDAR checkpoint、C16 前向特征统计、冻结层延迟与数值稳定性。
- MPC 80 ms 硬时限。当前冷启动已超限，必须做预热、稀疏求解/acados 或降低问题规模后重新测量。
- rosbag 场景回放、故障注入、轮离地低速试验和封闭场地验收。

这些条件对应 `configs/robot/r680_c16.yaml` 中的 `null` 字段和 23 个 `validation_gates`。在证据齐全前，不得批量设为 `true`，不得开启 `allow_nonzero_command`。

## 推荐下一步

1. 在开发机启动真实 C16 和底盘驱动，运行 `scripts/audit_ros2_runtime.py` 生成 ROS 图报告。
2. 按车型铭牌、URDF、TF 和低速试验结果逐项填写配置，并给每个验证门保留证据。
3. 提供 UniLION checkpoint 和对应代码版本，接入 `FrozenLidarBackbone` 协议并生成 C16 特征缓存。
4. 用 rosbag 回放执行延迟、丢帧、TF 中断和障碍物故障注入；优化 MPC 至满足硬时限。
5. 所有安全门通过后，先车轮离地，再以 0.10 m/s commissioning 上限做方向测试。
