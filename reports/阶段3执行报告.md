# 阶段 3：16 线点云与 UniLION 特征桥接执行报告

更新日期：2026-08-25

## 完成结果

- Gazebo C16 点云统一为 `x/y/z/intensity/ring/time` 六字段；仿真已知安装位姿从 `c16_link` 转换到 `base_footprint`。
- `ring` 按 16 条已知垂直束角推导，`time` 仅在 Gazebo 已知均匀旋转模型下由方位角和 0.1 s 扫描周期推导；真实 C16 不允许沿用该推导替代驱动时间戳。
- 连续采集 100 帧、720000 点，频率 10 Hz，每帧 7200 点，时间戳严格递增、全部有限，UniLION 配置空间平均空体素率约 0.999536。
- 在独立 Python 3.9/CUDA 进程对上述 100 帧逐帧执行冻结 UniLION LiDAR backbone。输出稳定为 `[1,384,180,180]`，特征方差中位数 `0.00104578`，最小值 `0.00104237`。
- 模型耗时中位数 `46.94 ms`，总耗时中位数 `61.17 ms`，P95 `61.72 ms`，最大显存 `474784256` 字节。
- FrozenSceneFeatures 通过 schema `1.0` 的缓存引用、SHA-256 和健康 JSON 跨 Python 环境传递；ROS 健康桥会校验 schema、时限、文件存在性和缓存哈希。
- 正常健康状态会发布 `/unilion/frozen_scene_features`；进程退出、健康超时、缓存损坏或非有限特征会令 `/safety/feature_stop_requested=true` 并向 `/cmd_vel` 发布零速。开发机已验证健康态和超时零速态。
- `/scan` 和 `/points` 几何路径保持独立，不依赖 UniLION，是 D-CBF 的确定性障碍物来源。

这证明的是“Gazebo 16 线点云 → 冻结 UniLION → 版本化特征缓存 → ROS 健康/安全桥”工程链路，不等同于真实 C16 精度验收。`frozen_backbone_verified_on_c16` 必须继续为 `false`，直到真实雷达连续 100 帧与实车外参、驱动时间字段完成验证。
