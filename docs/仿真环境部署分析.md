# 仿真环境部署分析

## 平台选择

计划文档首选 Ubuntu 24.04 + ROS 2 Jazzy + Gazebo Harmonic，但开发机当前是 Ubuntu 22.04 + ROS 2 Humble，已安装 Gazebo Classic 11 和 `gazebo_ros`，未安装 Nav2。遵循“算法主线优先”，第一阶段采用现有 Humble + Gazebo Classic，不升级宿主系统。Jazzy/Harmonic 留作第二套隔离环境。

## 第一阶段架构

第一版统一使用差速机器人：半径 0.22 m，速度 `[-0.1,0.6] m/s`，角速度上限 1.5 rad/s，线加速度 1.0 m/s²，角加速度 2.5 rad/s²。

仿真必须提供：`/clock`、`/tf`、`/tf_static`、`/odom`、`/scan`、`/points`、`/plan`、`/cmd_vel`。

- `/scan`：确定性几何安全通路和 D-CBF 障碍物。
- `/points`：Frozen LiDAR backbone 学习通路，模拟 16 线 C16。
- Gazebo model states：第一阶段障碍物真值。
- Nav2：全局路径、DWB 和 MPPI baseline。
- 本项目节点：候选、D-CBF-MPC、安全监督和最终 `/cmd_vel`。

## ROS 工作区拆分

建议在 `simulation/ros2_ws/src` 建立：

- `sim_robot_description`：差速底盘、2D 雷达、16 线 3D 雷达、惯导与 ros2_control。
- `sim_worlds`：8 类 world。
- `sim_bringup`：Gazebo、spawn、Nav2、桥接和控制器 launch。
- `ground_truth_obstacle_bridge`：Gazebo 状态到统一障碍物接口。
- `benchmark_manager`：场景重置、重复次数、超时和指标汇总。
- `dataset_recorder`：rosbag、冻结特征、teacher 标签。

## 八类场景和验收顺序

1. Empty：路径跟踪和控制稳定性。
2. Static Sparse：基础静态绕障。
3. Static Dense：多约束负载。
4. Narrow Passage：可行性和保守程度。
5. Crossing Pedestrian：横穿动态障碍。
6. Head-on：TTC 和停车/绕行。
7. Multi Dynamic：2–5 个动态障碍。
8. Local Minimum Trap：候选多样性与局部最优。

每一类先用 GT 障碍物，再依次替换为 noisy GT、几何聚类、学习检测。不要同时调感知与规划。

## 部署步骤

1. 安装 Humble Nav2、SLAM/地图依赖和 Gazebo ROS 控制包。
2. 建立差速 URDF/Xacro，验证 `/cmd_vel→odom→tf` 闭环。
3. 加入 `/scan` 并跑 DWB/MPPI baseline。
4. 加入 16 线 `/points`，先记录数据，不接 UniLION 控制。
5. 接入 GT 障碍 bridge 和本项目 D-CBF-MPC。
6. 实现 8 worlds 与自动 reset/seed。
7. 接 FrozenSceneFeatures bridge，UniLION 独立进程只发布特征。
8. 生成 feature cache、teacher label，训练候选和安全头。
9. 完成故障注入与 benchmark，再讨论 Isaac Sim/C16 域随机化。

## 进程隔离

ROS/Humble 控制进程继续使用系统 Python；UniLION 使用独立 Python 3.9/CUDA 12.4 环境，通过稳定的特征文件或 ROS 消息边界交互。不得把修改版 MMCV 安装进 ROS 系统 Python。
